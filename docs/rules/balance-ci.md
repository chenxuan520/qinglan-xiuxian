# 平衡门禁、体积预算与日报约定

> 改动数值、自动策略、CI 工作流、体积预算或日报前通读。本文件由 AGENTS.md 拆出，条文为用户已确认的约定，修改须经用户同意。

## 条文

- 完整游戏编译目录硬上限：`scripts/size-check.ts` 的 `distBytes` 为 18000000 字节（18 MB），递归统计干净的全部 Vite 游戏构建文件，含图片、音乐、Worker、监控入口与离线清单；不得只检查入口 JS/CSS 或自行调高预算。`npm run size:check` 检查独立构建，Pages 正式子路径构建及 Cloudflare 正式构建另对实际目录执行同一门禁，超过上限非零退出并阻止发布。Actions 后续恢复的每日统计报告与性能 JSON 属于独立报告产物，不计入游戏编译预算，不能把含报告的最终站点大小冒充游戏包大小。
- 修改战斗或成长后，运行相关测试；涉及整体难度时再运行 `npm run balance`、`npm run balance:trial` 或 `npm run balance:tribulation`。音频和文档改动无需重跑全部平衡模拟。
- 永久修为、境界门槛、法宝/功法、妖王或自动策略的数值改动须运行相关定向测试与原840条快检；10,080条完整矩阵统一交给每日定时执行，不在每次修改、推送或PR时自动追加，也不作为提交前必须本机重跑的检查；有额外明确需求时保留手动full入口。完整门禁用真实 `Game` 和正式结算，对七种灵根、正/魔/兼修、全部十种五行本命、手机/电脑场地和三个难度分别记录逐关进入率、连通率、成功/失败耗时、90 秒修为与境界、每只妖王实际出场与击杀时间，以及未击杀观测下界。裸开荒连续七关、一试即停；收益养成、仅广告复活/借寿、广告满根基/炼器三类另算，不能混成默认胜率。
- 用户最新确认的验收范围仅为**前六关**初入仙途无辅助连通率：天灵根目标 90%、允许 70–100%；异灵根 70%、允许 50–95%；双灵根 40%、允许 20–70%；三灵根 30%、允许 10–50%；四灵根 10%、允许 0–30%；五灵根 5%、允许 0–25%；无灵根允许 0–10%。容差是绝对百分点。这组要求覆盖旧的七关成仙目标；终关出场节奏按用户确认保留；妖王原招式恢复并撤去条带攻击，现有施法间隔保留，以boss-skills.ts及地域规则为准。默认样本无广告、训练、炼器、药物、宗门与重试，各根 120 个固定本命/路线/场地样本，不等于真人胜率。路线、本命和设备分组必须打印，分组差异单独诊断，不用旧的更严门槛否决用户已允许的整体区间。
- GitHub 每次 push 和 PR 跑 `npm run balance:ci`，只实际运行 840 条前六关无辅助样本；超出上述范围、异常、漏样本、重复样本非零退出。固定快检不扩成长矩阵。独立 Balance 快检链路还执行两个宽松性能门禁：`npm run perf:sim`（固定种子后期高压场景逐帧模拟耗时，只拦灾难性复杂度回归）与 `npm run size:check`（独立构建后入口 JS/CSS 原始及 gzip 字节预算）；每天北京时间中午 12:00（UTC `0 4 * * *`）与手动 full 另跑 `npm run perf:render`（无头 Chrome 恢复高压续局实测 60 秒帧率与长任务），只生成报告不卡关，产物不过仓库。每天北京时间中午 12:00（UTC `0 4 * * *`）与手动 full 跑 `npm run balance:gate:full`，实测 10,080 条当前七关全矩阵及重复首关；成长形状、首关 90 秒与技术完整性独立验收，第七关只报告。历史双向对照保留为 `npm run balance:gate -- --full` 的调研入口；不能把默认日测未执行的历史对照写成已经比较。跨大境界成本至少为上一小突破五倍、天灵根首局 90 秒九成达到炼气中期；当前收益提高属于用户授权改动，不以旧版低收益作为发布目标。
- push / PR始终只跑原840条快检及模拟/体积等独立门禁，不按数值文件变化启动全量或渲染采样；旧变更检测作业与脚本已移除。全量及每日渲染仅每天北京时间12:00定时或手动选择执行。同一仓库/分支的定时与手动全量共用并发组，新全量取消旧任务；普通推送不入组、不打断日测，不同分支和仓库隔离，快检保持独立。调整触发规则时让已经运行的长矩阵继续跑完，不为应用新规则手动取消。取消任务不生成或发布不完整日报，后续恢复也排除已取消的工作流。正常全量失败仍生成、上传并发布 master 报告，上传后的诊断验收遇到 Error、未通过或报告缺损必须让 CI 失败；Warning 不失败、不擅自改用户容差。恢复保留历史可信master push报告及当前快检性能来源，排除PR与外仓，不回退最新失败；接受历史产物不代表恢复推送全量触发。失败邮件由 GitHub 个人 Actions 通知设置控制。
- 每日完整报告地址：<https://chenxuan520.github.io/qinglan-xiuxian/balance-report/>。报告包含源提交、时间、失败、七关实测与投入/路线/本命/场地分组，可组合筛选，汇总维度可多选或全部取消合计，分组分页与图片导出须标明规则和当前页；可生成/保存统计图；图表只在明确点击生成或翻页时重画，筛选、汇总维度和图表类型变化后保留旧图并标记过期，重新生成前禁止导出。失败与诊断放在统计前面，明细默认折叠、点击展开，计数与通过状态保留可见；Error 红色、Warning 黄色；同目录 `diagnostics.json` 提供给本地 AI 的结构化 GET 接口，详情见开发文档。失败日报也更新且工作流仍失败。生成的 HTML、JSON、CSV、截图、整批存档和研究日志只放已忽略 `artifacts/` 或 `/tmp`，**不提交 Git，也不建立 gh-pages 分支保存报告**。报告通过 Actions artifact 组成 Pages 部署；日报发布保留最近成功游戏部署，游戏发布保留最近正式日报。页面更新有排队延迟，失败邮件沿用 GitHub Actions 个人通知设置。
- 培养倾向独立小测试：`npm run balance:autoplay`（`--plan`预览），固定双灵根/兼修/手机/初入/无辅助、十种入门本命各四个开局；五模式各40条连续前六关，共200条，不向840/10,080矩阵乘入模式维度。独立`autoplay-balance.yml`每天北京时间12:00与手动运行；两站监控在「每日测试与诊断」之后显示对照，公开JSON为 <https://chenxuan520.github.io/qinglan-xiuxian/autoplay-report/summary.json>。同开局种子配对但决策后随机进程可能分叉；指定法宝固定玄冰镜＋白骨髅，小样本不代表真人胜率。技术异常/漏重样本/混合版本CI失败并展示失败摘要，低通过率不自动改游戏或门禁；报告只进入Actions artifact和Pages，四条发布链相互保留报告，取消任务不发布。
- 36 件法宝独立实战测评：`npm run balance:weapons -- --extended`；`--plan` 只预览，`--weapons orbit,pagoda,talisman` 可筛选，`--seeds` 扩样，`--seed-offset` 换种子，`--workers` 控制并行。默认主矩阵 8,640 条，完整套件 10,400 条计划记录（另计配对两侧及连续流程中的实际战斗数）；自然第一/三/六关与后段同投入配对分开报告，不当作真人或连续通关胜率。每日北京时间12:00的 `weapon-benchmark.yml` 跑标准完整套件，报告 <https://chenxuan520.github.io/qinglan-xiuxian/weapon-report/>，两站 `/monitor/` 展示摘要，`summary.json` 为公开接口。技术异常、漏样本或混合版本使CI失败；强弱差异仅供诊断，不擅自设数值发布阈值。报告只上传Actions artifact并部署Pages，不入Git；发布链路相互保留平衡、性能与法宝日报，取消任务不发布，正常失败显示失败日报。
