## 行前提示与街巷说明

`preparation-advice.ts` 只读当前行囊，依次比较本命炼器、可承担的较低阶根基和未生效的时效丹；费用、折扣、年岁与可服条件调用原规则。仅在普通历练失败结算页显示文字，首页和通关成功页不渲染该建议，不自动消费或增加战斗步骤；未完历练、寿尽、欠供奉、天劫等状态收起建议。建议不推断败因，也不承诺通关。`training-preview.ts` 固定当前搭配与年岁，仅增加所选根基一级，经 `spiritPower` 的真实 `Game` 入场计算对比气血、本命伤害与移速；洞府三卡与结算建议共用，不改变修习消费或平衡。

`settlement-directory-source.ts` 在人间面板的去处清单主动展开后才加载 `settlement-directory.ts`，避免把坊市报价模块并入首页。加载合并与离线资源沿用 `ModuleSource`；完成时重读当前存档，收起、离开或锁档后不写入迟到结果。冷加载失败时浏览器会缓存共享依赖的失败，单给入口加片段不能可靠恢复，因此这里只显示受保护的 `refresh-game`「重新加载」，保存未成功时留在原页。清单只解释既有事务，真实办理仍走原预检及保存流程。`human-recollection.ts` 仅提示已经相识、当前可回访的旧事或已发现的未读家书，不提前暴露陌生人物和家人结局；茶馆旧书通过 `assetUrl('novel/')` 主动新开独立阅读页，不读写游戏存档、不替代听书结算。

## 本地运行

需要 Node.js 22.18+ 和 npm。

```bash
npm ci
npm run dev -- --port 5173 --strictPort
```

打开终端显示的地址，默认是 `http://localhost:5173`。手机与电脑在同一局域网时，可使用终端显示的 Network 地址访问。

```bash
npm test           # 战斗、成长、存档与立绘映射测试
npm run build      # TypeScript 检查与生产构建
npm run preview    # 预览 dist 中的生产版本
npm run balance    # 固定种子的难度与六境连续战斗模拟
npm run balance:training # 天灵根与普通双、三灵根的连续六境及悟道终关对照
npm run balance:realms -- --roots=heaven --seeds=307,619,997 # 不强化、不复活的七境顺推对照
npm run balance:passives # 三路线、三灵根的终关功法对照
npm run balance:trial # 四档境界的终关挑战模拟
npm run balance:tribulation # 五次天劫的满配 AI 模拟
npm run balance:ci # 每次提交：840 条前六关裸开荒目标验收与日志
npm run perf:sim # 每次提交：三档后期高压场景的每帧模拟耗时基准
npm run size:check # 每次提交：独立目录构建并校验入口 JS/CSS 体积预算
npm run perf:render # 每日与手动：无头 Chrome 实测 60 秒帧率与长任务（仅报告）
npm run balance:gate # 扩展回归；核心改变自动强制完整目标门禁
npm run balance:gate:full # 三难度、20 样本/组、用户确认的裸开荒与成长目标
npm run format:check
npm run check:npc-ai # 生成 Worker 类型并检查独立后端
```

永久修为的关卡系数、妖王奖励和固定敌人定标位于 `src/data.ts` 的 `STAGE_CULTIVATION_RATES`、`STAGE_BOSS_CULTIVATION`、`FIRST_STAGE_CLEAR_CULTIVATION` 与 `STAGE_REALM_STEPS`；击杀累加在 `src/game.ts`，境界门槛与结算在 `src/progress.ts`。对局规则与存档结构共用当前版本：当前结构版本以 `src/progress.ts` 的 `SAVE_SCHEMA` 为准；旧版存档在 `readSave` 单点归一，保留永久进度、补齐可选默认字段，放弃旧格式的未完成对局，不维护逐版本运行时分支；更高版本只读不写。调整数值时同步 [永久修为说明](gameplay.md#永久修为与秘境推进)、游戏内指南和 [验证记录](verification.md)。

第三至六境精英节奏配置集中在 `src/data.ts` 的 `ELITE_PACING`，波次调度与出生气血在 `src/game.ts`。精英节奏与后半程波次为固定规则，恢复时不重新放大在场敌人气血。`lateEliteWaves` 记录是否已接上后半程波次，与 `nextElite` 一起保存，恢复时不重新放大在场敌人气血。变更覆盖波次边界、精英上限、暂停恢复与快照校验时，运行 `tests/elite-pacing.test.ts`；完整难度和分灵根对照见 [验证记录](verification.md)。

灵威概览仍由 `src/spirit-power.ts` 使用真实Game计算；履历详情在 `chronicle-content.ts` 按需加载，`chronicle-source.ts` 按当前构建清单重试，关闭后迟到回调不重开。`power-breakdown.ts` 固定实际入场本命与路线，逐项移除来源重算，不复制战斗伤害公式；`spiritPower` 的可选路线仅用于此项对照，默认行为不变。`power-details-ui.ts` 展示完整数值及正负增幅；所有行是各自与移除状态比较，不能相加。新模块随完整离线资源缓存，不新增存档字段或依赖。

根基收益在 `src/training.ts`：悟道用 `powerTrainingEffect(n) = n + 0.1 × max(0,n−10)^2`，淬体/身法仍用 `trainingEffect`，前十阶与修炼费用、年岁均不变。献物专长用一次固定折价覆盖最少连续阶数，差额补灵石；逐阶年岁向上取整到0.1后相加，供奉单独预留。剩余境界/满阶额度不足以用完整份抵价时零消耗拒绝，不产生可结转余额；精研每阶真实结算，保留五/十阶赐丹。办理仍经 clone→writeSave→apply，写入失败不扣物、修习或记冷却。

`balance:realms` 不会购买永久强化，不能用它代替“正常投入所得资源”的通关测试。两种策略的样本、参数、逐关境界和局限见 [天灵根逐关成长验证](verification.md#天灵根逐关成长复核2026-10-03)。外部辅助模拟与原始结果不随仓库分发，现有命令与外部脚本的复现范围分别说明。

`balance:ci` 每次提交只运行 840 条**前六关、初入仙途、无辅助**真实路线：七种灵根 × 正/魔/兼修 × 手机/电脑 × 20 固定种子，合法本命轮换，共覆盖十种五行本命。无广告、训练、炼器、丹药、宗门或重试，成功为 `cleared >= 6`，不能称作成仙。本轮新规则单独运行实测 Node 24 约 2.2 分钟、Node 22 约 2.6 分钟，逐局数据完全一致；GitHub 托管机器实测约 5 分钟，与完整矩阵并发的本机实测约 6.2 分钟。耗时按实际日志记录，不能保证所有机器固定两分钟完成。当前引擎只跑一遍，源依赖摘要用于记录和防止运行中源码变化，不再为快检追加旧引擎或长矩阵。

用户最新确认的整体通过率硬门槛（绝对百分点，覆盖旧七关目标）：天灵根 70–100%、异灵根 50–95%、双灵根 20–70%、三灵根 10–50%、四灵根 0–30%、五灵根 0–25%、无灵根 **0–10%**。异常、漏样本、重复样本、错误妖王身份/死亡记录及越界通过率都非零退出。计划分母不因缺失样本减少。路线、本命和手机/电脑分别打印；分组差异单独诊断，不混入玩家未授权的额外整体目标。

每次快检在已忽略的 `artifacts/balance-ci/` 生成 JSON、逐战 CSV 和中文摘要，直接打印灵根逐关、路线、本命、场地、耗时与妖王统计，并写入 GitHub Actions Summary。成功或失败均保留 artifact 14 天。失败邮件使用 GitHub 自带 Actions 通知，仓库代码无法替用户开启个人邮件设置（GitHub Settings → Notifications → Actions → Email / 仅失败）。

每天**北京时间 12:00**（UTC cron `0 4 * * *`，可能排队延迟）运行 `balance:gate:full`；也能在 Balance gate 手动选择 full。完整矩阵共 10,080 条：七根 × 三路 × 两场地 × 四种投入 × 三难度 × 20 固定种子。裸开荒一试即停，收益养成、仅广告复活/借寿、广告满根基炼器分别统计，其他投入至多每关 5 次且有有限操作预算。记录七关进入率、累计连通率、成功/失败耗时、90 秒修为/境界、每只妖王实际出场、击杀或存活观测下界，不能把未进入或未击杀记成零秒击杀。另做真实重复首关，首通修为只能领一次。默认完整命令只验收当前矩阵，保留前六关通过率、首关天灵根 90 秒九成中期、跨大境界至少五倍和技术完整性硬门槛；终关按用户确认只展示实测，妖王演出和本命差异列诊断。

push / PR 只执行原840条快检、模拟性能及构建体积门禁，不按数值文件变化追加10,080条完整矩阵或渲染采样；旧变更检测作业和脚本已移除。全量与渲染仅每天北京时间12:00定时或手动选择执行；手动full运行完整矩阵与渲染，render_only仅渲染，两者同时选中时以render_only为准。全量作业按「仓库＋分支」共用并发组，同分支新的定时或手动全量取消旧全量及排队任务；普通推送不入组、不打断日测，不同分支和仓库互不取消。GitHub以任务进入并发组的顺序选择保留者，不保证提交时间顺序。

完整作业在门禁失败后仍生成并上传 HTML、原始结果与 `diagnostics.json`，上传后由 `scripts/check-balance-report.ts` 严格核对诊断：Error、未通过、缺文件 / 坏 JSON / 协议或计数无效均非零退出；Warning 仅打印、不改验收区间。被取消的全量作业跳过日报生成、上传和诊断验收，不让取消造成缺报告错误；发布作业同时排除被取消的依赖，后续游戏发布也排除已取消工作流，避免不完整矩阵覆盖原日报。正常失败仍通过 `always()` 发布本仓库 master 报告，整个 Balance gate 保持失败，沿用 GitHub 个人 Actions 失败邮件通知。后续游戏发布会保留最新完成的正式报告，不因失败而回退旧的绿色结果；恢复仍接受此前已完成的可信master数值push报告，快检性能同样保留push来源，均不重新触发全量。报告显示实际时间与源提交，不冒充当前游戏的测试版本。

历史双向研究入口 `npm run balance:gate -- --full` 仍冻结 `d10f276` 作真实旧引擎对照（所有产品源码一致才复用），比例 ±10 个百分点、耗时中位 ±20% / P90 ±25%、妖王存活 ±25% / ±30%、修为 ±20% 等旧版本差异如实记录。它不是默认两分钟 CI 或日测，不能把本轮明确授权提高的收益判成未授权差异；不自动更新基线。报告路径只允许 `artifacts/` 或 `/tmp`，不得删失败样本、截掉掉落物或伪造通过。

## 性能门禁与渲染实测

性能回归防护分两层，源码在 `scripts/perf-sim.ts`、`scripts/size-check.ts` 与 `scripts/perf-render.ts`，产物均写入已忽略的 `artifacts/` 不提交仓库。

- `perf:sim` 每次 push / PR 在独立 Balance gate 快检中执行，不放入 Pages 部署链路：固定种子在 Node 里驱动真实 `Game`，场景为第六境后期满配自动历练 90 秒、第七境满配逢妖王 90 秒、第六境妖王弹幕 75 秒，逐帧计 `g.update` 耗时统计均值 / p50 / p95 / 最差帧与敌人、弹丸峰值。预算为宽松兜底（p95 ≤ 4ms，最差帧 ≤ 60ms；2026-10 本机基线约 p95 0.12–0.62ms），只拦战斗模拟的灾难性复杂度回归，不随机器快慢抖动；超出预算或场景持续推进不足 30 秒非零退出。
- `size:check` 同源链路执行：独立目录 `artifacts/size-check` 以根路径构建后按 `index.html` 引用定位入口 JS/CSS，校验原始与 gzip 字节（JS ≤ 560,000 / gzip ≤ 210,000，CSS ≤ 160,000 / gzip ≤ 35,000；2026-10 基线 451,039 / 169,642 / 125,815 / 27,266）。防止依赖或素材误打进产物。入口 JS 预算在 2026-10-14 由 550,000 调到 560,000，用来容纳主界面控制器拆分后的函数边界；入口 CSS 预算在 2026-10-28 经用户确认由 150,000 放宽到 160,000。
- `perf:render` 每天与手动 full 一起跑（`perf-render` job，不卡门禁）：无头 Chrome（CI 的 ubuntu-latest 自带 google-chrome，本地用 `CHROME_PATH` 指定）加载根路径独立构建，写入一份自动生成的「第六境后期满配」可恢复存档（`perfSaveFixture()` 用真实 `Game` 模拟 10 秒后快照），恢复历练后采样 60 秒 rAF 帧间隔与长任务，输出 `artifacts/perf-render/report.json`、`summary.md`，仅保留数值报告，不生成或保存截图。无头软渲染远低于真机帧率，数据仅作日报观测，不设门槛，不与真实设备比较；浏览器或页面流程出错才非零退出。不引入任何新依赖：直接用 Node 22 内置 WebSocket 走 Chrome DevTools Protocol 驱动浏览器（`scripts/perf-render.ts` 自带极简 CDP 客户端），避免浏览器驱动库拖入安装链。使用独立临时浏览器目录并在退出后清理，采样视口固定为 1365×900，保持每日基线一致。

手机战斗的画布精度由 `battle-resolution.ts` 根据实际绘制帧间隔调节：仅粗指针设备的进行中战斗采样，每个至少1.6秒的窗口低于35FPS时降低0.25倍像素密度，最低1倍（设备本身低于1倍则沿用设备值），最高沿用原来的设备密度且不超过2倍；连续四个窗口达到55FPS后才提高一级，避免频繁切换。暂停保留精度、清空采样；超过1秒的间隔或时间回退不计慢帧，首页和桌面恢复原精度。只改变主画布的物理像素，不改变CSS尺寸、视野、战斗时钟、敌人、弹丸、伤害、预警或AI；HTML信息栏不降精度。CPU降速与触屏模拟只用于同环境对比，不能换算为实体手机FPS。

`render.ts` 在原有96项有界纹理缓存中复用飞剑及两种经验光点，动态招式和位置仍逐帧绘制；屏幕渐变按尺寸复用，尺寸变化或上下文恢复时重建。`hud-layout.ts` 用 `ResizeObserver` 观察计时栏、妖王栏和顶部信息栏，合并到下一帧先读位置、再写实际发生变化的定位变量；旧浏览器无该API时逐次合并测量。HUD重建、回到首页和导览换场/退出必须释放观察与待办帧，不能持续持有已移除节点。药效换行、妖王显隐及横竖屏切换仍要实际检查定位。 战斗年岁与计龄速度合在一行，超长显示省略号；手机药效同样只占一行，完整药名和剩余年数保留在DOM及title，桌面药效仍逐种换行。手机竖屏年岁与药效为9px、横屏8px，长年数沿用紧凑数字显示，不改变实际时长。
屏幕常亮由 `screen-awake.ts` 单独管理，不申请方向锁。只在前台自动历练时持有，暂停/关闭/结算/后台释放。方向、全屏与恢复焦点事件重新核对常亮；系统首次收回可立即补申请一次，30秒内连续收回仍限频，拒绝请求不阻断战斗。异步返回时使用代次检查，旧显示状态的锁立即释放。实测须区分浏览器API夹具和实体手机，不能据模拟结果承诺特定设备的系统支持。

小镇与坊市的移动立绘通过 `settlement-sprite.ts` 保留脚点与前后层级，使用 transform 位移，静止时不重复写样式；屏外移动人物只隐藏视觉节点，真实坐标、身份与交互计算照常进行。装饰人流和坊市访客的视觉更新至多每秒30次，主角与镜头逐帧更新；镜头平移不重复写入缩放变量，也不取消人流节流。两场景在视口节点启用CSS containment；不改变地图、碰撞、走速、计龄、交易和存档规则。

可见移动立绘的外层设置 `will-change: transform` 合成提示，屏外隐藏时清除，返屏时恢复。地图沿用原有节点与范围，镜头平移使用等值的 `translate3d(x,y,0)`；小地图SVG使用 `translateZ(0)` 独立合成，减少移动与坐标点刷新时的重绘压力。不额外拆分静态建筑层，不改变脚点、z序、缩放、小地图位置与交互规则。

## 隐藏物资调试

在「关于」面板的版本号上，七秒内连续点击七次，打开物资调试。设置与首页没有调试菜单。可增加灵石、玄铁、指定法宝与炼器阶数、丹药和奇物，也可增加指定整数永久修为，或直达所选境界（含各小境界，最高渡劫）；直接写入原来的 `qinglan-immortal-v1` 存档，关闭调试仍保留。法宝只进入收藏，不替换本命；丹药不自动服用；重复法宝保留较高炼器阶数。奇物每件本世仅可领取一次，已得与已售奇物不再列入可发放物品。成功发放后保留当前选中奇物，立即显示持有一件并禁用发放按钮；选择另一件未获得奇物后才恢复发放。未完成历练、已落幕、待轮回或劫修遭遇期间禁止发放。成功发放后关闭本机匿名统计，避免调试进度混入普通游玩汇总。

NPC Worker 提供 `GET /debug/access`，返回 `{ "enabled": true/false }`，沿用官网、GitHub Pages 与本机的来源校验，响应 `Cache-Control: no-store`。只有 `DEBUG_MODE_ENABLED` 明确为字符串 `true` 时开放；未配置时默认关闭。仓库不声明该变量，`deploy:npc-ai` 使用 `--keep-vars` 保留线上开关，普通发布不会再把已开启状态覆盖成关闭；仅添加该参数但仍在配置中声明同名变量不能保留线上值。测试需要时，可以显式开启：

```bash
npm run deploy:npc-ai -- --var DEBUG_MODE_ENABLED:true
```

关闭时执行：

```bash
npm run deploy:npc-ai -- --var DEBUG_MODE_ENABLED:false
```

修为调试只增加不倒退；点数必须为正整数且不能超过到渡劫的剩余额度，超额整笔拒绝。直达境界补足真实累计门槛，不改变年岁、本命或通关记录；不会直接成仙。到达渡劫后两种发放均禁用；已通终关的真仙不再发修为。突破年表与大乘天劫时钟随真实进度同步，旧存档无需增加字段。

开关只需发布 Worker，无需重新编译游戏；部署时应核对 `GET /debug/access` 的真实返回。进入面板和每次发放都重新核验，已打开面板不能沿用旧许可；断网、五秒超时、非成功状态或错误响应格式都拒绝。关闭面板或离开「关于」后，迟到响应不得打开面板或发放物资。发放先构造副本，存档写入成功后才应用；不添加独立调试存档或保存结构版本。此开关控制正常客户端的调试入口，不提供账号鉴权，也不改变本地存档可自行编辑的性质。

## 存档结构与恢复

本机存档由 `src/main.ts` 的 `writeSave` 统一写入浏览器 `localStorage`，键为 `qinglan-immortal-v1`。永久修为与本局已入账数额同存，结算收益与结束对局在同一次写入中完成，防止刷新重复发放。普通进行中对局每五秒保存，暂停、升级选择及离开页面也保存；普通异常中断至多退回最近检查点。恢复战况包括位置、气血、法宝、功法、敌人、弹道、掉落、时间、选项、重悟、复活、伤害统计与妖王进度，恢复后先暂停。极限中断规则见[此世模式与战斗中断](#此世模式与战斗中断)。

结构版本由 `progress.ts` 的 `SAVE_SCHEMA` 决定。`readSave` 是本机读取与文件导入共用的旧档归一入口：保留永久进度、补齐默认字段，不兼容的普通未完对局放弃；极限未完战斗按中断处理。更高版本的本机档只读不写，提示刷新并允许下载原文；文件导入拒绝更高版本。旧档缺少路线字段时按兼修处理，新角色与轮回则默认正道；已开始对局保留原路线与装备。

周期天劫迁移沿用 `syncTribulationClock` 与 `restoreSavedRun`：旧大乘档若尚无天劫时钟，从读取时的当前年龄起计两万年，不追罚历史年岁。已有第七境通关记录则清除周期天劫时钟；旧档正在迎劫时，恢复被暂停的原历练，没有原历练则返回首页，不补发天劫奖励，已有劫印保留。

`save-transfer.ts` 接受本游戏导出包装及原始存档 JSON，按 UTF-8 字节校验 10 MB 上限，校验后先展示摘要，确认且保存成功才应用。离界赠物标记只在少年命盘接受前保留；与新生库存不符时拒绝文件导入，本机读取丢弃无效标记而不补造遗物。已保存的极限未完战斗导入仍按中断判死，不将文件导入当作撤离。

无法识别的本机原文先备份到 `qinglan-immortal-v1-unreadable-<时间戳>`，相同内容只备份一次；用户可下载原文，确认开始新世前不覆盖旧档。每次写入前比对当前存档与本页上次读写内容，并监听其他标签页的 `storage` 事件；跨窗口冲突后暂停且停止写入，只允许载入最新进度。保存失败、无效导入和迟到回调不得部分扣费、发奖或覆盖进度。

妖王招式名称、池与间隔集中在`boss-skills.ts`；终关旧王编号0～2保持原招式，地域招式只追加，仙尊仍六招。队列按实际战场校验范围，终关幻影与二段连扑可暂停、导出与续局。双王无施法互锁，终关妖王地域场不受普通场数量预算截断，普通妖物与前六境预算保留。此次语义扩展将SAVE_SCHEMA递增为30；旧档永久进度仍由readSave统一迁移。妖王快照保留下一招、当轮余招、出场排程、延期与首招设定；弹幕保存来源、位置、速度和盘旋阶段，恢复不会重新抽招、反复放大敌人或重播已经落地的伤害。损坏快照不恢复对局，但按存档读取规则保留有效永久进度。

## 此世模式与战斗中断

`SAVE_SCHEMA = 27`，`SaveData.lifeMode` 只允许 `normal` / `extreme`；旧档缺失字段按普通处理，非法值拒绝读取，不为老档额外弹出迁移步骤。每世在命盘接受前选择，选择和确认均先写入再应用；普通轮回和离界新世默认普通。极限最低秘境难度为下标1，周期天劫的内部难度0及强度公式保留。

极限秘境、周期天劫均先构造副本并保存初始快照，再挂载战斗；失败留在入场前。`restoreSavedRun` 在恢复前检查极限未完快照、天劫返场及劫修遭遇，统一通过 `endExtremeLife` 标记 `pendingReincarnation: extreme`；坏快照不回退成活着的大厅。普通旧对局迁移仍保留永久进度。胜利只通过原子结算写入，普通胜局不保存不可恢复的 `won` 快照；失败不得部分发收益。周期天劫胜利先保存劫印及原历练，再展示结果，未完原历练仍受中断保护。

界面置灰之外，动作路由和广告异步回调同时拒绝奖励；未完战斗（含天劫后的 `pendingRun`）阻断退场、放弃、重开、导入和主动轮回，文件读取前后再核对。后台暂停不等于退出；重新载入/关闭后重开以及 bfcache 恢复未完战斗按中断处理。bfcache 保留的已胜未结内存继续结算，不误判身陨。保存失败与跨窗口锁定仍优先，死亡保存失败停在可重试的原页，不能继续行动。

「尘缘初结」为留下一段人间旧事；「逆天改命」为天劫降临难度成仙，旧年表名称只在展示时统一，不改达成标识或原文。「生死证道」只在极限七境全部胜利结算达成；删除「以物结缘」成就，保留真实交易年表。成就显式设置 `difficulty` 并由易到难排序，新增不得直接堆在末尾。留影评语、图像留痕同步识别新成就与 `extreme` 结局；监控与轮回打点把该结局展示为「极限身陨」。

## 此世道果计分

`journey-score.ts` 仅从本世状态派生分数，不写入总分或额外累计字段。沿用永久灵威、拙根逆命、通关/成就和外缘扣分；先以 `round(rawScore × clarityFactor)` 得到 `clarityTotal`，极限再以 `round(clarityTotal × 1.15)` 得最终总分，普通系数为 1。`clarityDelta` 与 `modeDelta` 分开，履历构成把后者单列为「一命问道 ×1.15」，不会把极限收益算进道心澄明。既有成就分与战斗/成长数值不变。

`journeyScoreTier` 按最终总分统一判定八档，起分依次 0/100/250/450/1000/1500/2000/2500；极品以上为仙品、帝品，当前称号与规则表见玩法文档。普通与极限共用分档；履历与 `journeyCardData`/PNG 使用同一最终计算结果，图片道果行显示「分数（品第·称号）」。导入、刷新与重复生成按原事实重新计算，不叠加旧分，无须变更存档结构版本。

## 可选离线资源缓存

首页右上角音量旁的齿轮打开设置，不占用修行菜单；自动历练复用原存档状态与操作，手机首页（窄屏或触屏，含横屏）隐藏快捷开关，电脑首页保留。设置内切换后更新同一面板，保留滚动、展开状态和焦点；手机自动全屏只在明确入场操作的点击调用栈内请求，不从资源加载回调或切回 App 的事件中重试，默认不锁屏幕方向，手机可在设置中明确选择竖屏或横屏，支持时在全屏后锁定；窄屏只调整首页控制区排布，沿用按钮尺寸，不影响战斗栏。`src/settings-ui.ts` 渲染独立设置面板，声音控制复用现有音频实例、存档字段与 `data-volume` 事件；离线资源小节每次打开面板默认折叠，音量调整和缓存进度刷新保留当前展开状态。`src/offline.ts` 管理设置面板的缓存操作；只有点击「缓存所有离线资源」才注册 `public/offline-worker.js` 并获取全部资源。完成过缓存的浏览器重新打开时只检查既有缓存，不自动缓存新版本。缓存与 `qinglan-immortal-v1` 存档独立，清除缓存不读写存档。

「清除所有缓存资源」始终显示在离线资源小节；检查、缓存或清除过程中暂不可点击。清除只删除 `qinglan-offline:<当前作用域路径>:` 前缀的资源缓存，即使 Service Worker 已注销，也能清理残留完整缓存和未完成缓存，不删除其他作用域或网站数据。操作锁覆盖整个清除过程；状态检查按请求序号丢弃迟到响应，避免关闭重开面板、声音切换或并行检查把旧状态写回。其他页面重新完成缓存后，状态检查会撤掉旧清除提示。

Vite 的 `scripts/offline-build.ts` 为每次生产构建生成 `offline-manifest.json` 与带构建号的固定清单；收录整个构建输出，包括后台计时 Worker、指南与留影懒加载代码、音乐和未访问关卡素材。远程公共字体不纳入清单，离线使用系统字体。`public/` 中以点开头的本机文件或目录（如 `.DS_Store`、`.opencode/`）会从构建输出删除，不进入部署目录、离线清单与体积统计。清单包含文件长度与 SHA-256，缓存逐项校验，全部成功后才写完成标记。网络、空间不足、取消或部署中途资源变化均不能标为完整。保持根路径与 GitHub Pages 子路径的独立作用域。

导航先请求网络，失败或三秒无响应时使用最新完整离线入口；静态资源优先使用完整缓存，公共素材和 CSS 中的图片带构建号，避免两版图集混用。音乐缓存完整文件并支持 `Range` 的 206 响应。仅缓存清单内静态资源，AI 与统计 API 不入缓存，广告机制不改。成功更新后保留最近两套完整资源；更早的旧页面需刷新后使用新版。发布必须携带生成的固定清单与 `offline-worker.js`，不能只上传 JS/CSS；本机正常入口更新时也须先追加这些公共文件，再原子替换 `index.html`，保留旧 hash 文件与固定清单。

资源或按需模块加载失败时，`update-check.ts` 请求最新 `offline-manifest.json`（禁用缓存并附检查参数，5秒超时），只有确认构建号不同才显示「游戏已更新，请刷新后继续」。同版、断网与异常清单不误报，原加载重试及离线回退继续可用。尚未进入的场景只留一个「重新加载」：贴图和秘境预载原地重试；小镇与坊市模块失败则保存后刷新页面，再从正常入口重进，避免浏览器缓存失败的静态子依赖。点击刷新前必须确认当前存档与未结算状态可安全保存，保存失败/锁定/待结算时留页提示；不自动刷新，不清除资源缓存或存档。`module-source.ts` 统一并发加载与当前构建的固定清单重试；指南与妖物志共用指南模块，离线清单包含二者，加载后再次打开直接复用，迟到回调须同时核对面板、分类和存档锁定。

`npm test` 覆盖完整性、版本切换、中断、空间不足、失效检测、作用域隔离和音乐范围请求；`tests/offline-controls.test.ts` 另覆盖注销后的残留清理、清除时重开面板与重复操作、其他页面重新缓存、迟到及乱序状态响应，检查实际文案、按钮、缓存与存档结果。浏览器使用 Chrome DevTools MCP，在正常入口的隔离存档下验证实际缓存、断网导航、未访问地图和清除后的存档。离线功能需要 HTTPS 或 localhost 的安全上下文；普通局域网 HTTP 地址可能不支持。

`check:npc-ai` 先创建输出目录，再将 Wrangler 类型生成到忽略提交的 `artifacts/npc-ai-env.d.ts`，并用独立 tsconfig 检查 Worker。GitHub Actions 同步执行此检查，但只部署静态站；Worker 和 Cloudflare Pages 分别发布。更换对话地址时可在构建环境配置 `VITE_NPC_AI_URL`，默认域名、模型、前后端超时、消息和历史长度、输出参数集中在 `src/setting.ts`，镇民换代年限及百年城景间隔也在该文件。域名绑定、CORS 和边缘限流在 Worker 的 `wrangler.jsonc`。

服务端按 `Origin` 完整匹配公网来源：`https://xiuxian.011203.xyz`、`https://chenxuan520.github.io`。本地另允许 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP / HTTPS 任意合法端口（含默认端口），不用逐个加入白名单。拒绝其他 Pages / GitHub 站点、后缀相似域名、混入路径或凭据的来源、多个来源、`null` 或缺失来源。除公开聚合监控 GET 外，所有路由（包括 `/health` 与预检）先校验来源，不通过时返回空的 403，不读取请求体、不调用 AI，也不返回 CORS 放行头。白名单配置空项不会放行无来源请求。部署新的游戏域名时同步更新 `ALLOWED_ORIGINS`；浏览器自动携带来源，手动健康检查也需带允许的 `Origin`。来源检查用于限制其他网页调用，非浏览器脚本可伪造该请求头，不能替代限流或身份认证。请求体最多 8 KB，玩家消息最多 200 字，历史最多六条；对白按来源 IP 每 60 秒允许 12 次请求，配图独立限制为 2 次，限流是边缘节点级保护，不是登录认证。普通闲谈的模型输出最多 512 tokens，关闭深度思考以保证短对白响应，只展示最终回答，Worker 推理超时 12 秒，客户端 20 秒；失败回退本地台词，不自动重试普通闲谈。关闭对话会取消请求并通知上游，返回文本用 DOM 文本节点展示，不能执行 HTML 或修改游戏存档。

茶馆首次听书优先讲述 `src/local-tea-stories.ts` 的陆迟《不系舟》篇，联网版、离线访问与单机版共用同一正文，不调用AI或配图；在正文成功显示且面板仍有效后，才由 `tea-story-memory.ts` 写入独立本机键 `qinglan-tea-luchi-heard-v1`。取消、关闭、脱离DOM和被新一回替代的回调不标记；轮回不清此键，储存被拒时只记当前页面。之后单机轮换另外三篇本地旧闻，联网版按原规则请求新故事。

联网新故事复用 `POST /chat`，请求带 `mode: "tea-story"`，仅接受 `npcId: "tea"` 和空历史；与闲谈共用来源检查和每 IP 限流。`TEA_STORY_SETTINGS` 单独设置 1400 tokens、900 字上限、服务端推理 50 秒 / 客户端单次 60 秒超时，给预检、连接和返回留余量，提示生成 320–500 字的完整修仙故事。网络中断、超时、可重试的 5xx／408、空内容最多自动尝试两次，间隔 600 毫秒，最坏客户端等待约 120.6 秒；400／403／429 等不自动连刷，服务端不再叠加重试。关闭会取消当前请求与重试等待，不把主动取消提示成生成失败。自动尝试仍失败时显示具体原因与「重试这一回」，只重发生成请求、不再消耗年岁或判定机缘；成功后才启用「再听一回」，沿原听书结算另耗半载并判定一次机缘。正文以 `textContent` 展示，不写入存档，不控制奖励，不用固定文本冒充新故事。

正文响应会附带与内容绑定、五分钟有效的 HMAC 配图令牌；签名密钥通过 `wrangler secret put STORY_IMAGE_SECRET --config workers/npc-ai/wrangler.jsonc` 配置，不写入仓库。正文写入页面后，前端才携带原文和令牌异步请求 `POST /story-image`，因此图片生成不会阻塞故事，接口也不能用来提交任意图片提示。Worker 固定使用 `FLUX.1-schnell` 的 4 步推理和无文字、无标志的国风修仙画风，客户端不能指定模型或提示模板；返回 Base64 图片会在 Worker 内转为 JPEG，前端限制为 5 MB，并以临时 Blob URL 淡入故事背景。图片推理预算 28 秒、客户端 40 秒，不自动重试以免放大配图额度消耗。图片限流、令牌失效、超时、生成失败或错误格式会提示「配图暂未生成，不影响阅读和朗读」，不修改正文、奖励或存档；关闭及替换弹窗会取消请求并释放临时 URL。

Worker 失败响应包含安全的 `error`、中文 `message`、`retryable`、`requestId` 与兼容字段 `fallback`。`inference-timeout` 为 504、`inference-failed`／`limiter-unavailable` 为 503、`empty-reply`／`empty-image` 为 502、主动取消为 499；429 `busy` 附 `Retry-After: 60` 并允许跨域读取。日志按请求编号记录路径、模式、阶段、耗时和经过筛选的错误类型／数字代码，不记录正文、提示词、密钥或异常原文。显式 deadline 即使 binding 忽略取消也会结束 Worker 等待，但不能保证上游计费同步停止；该预算仅覆盖推理，前端总请求超时仍作为保护。`/health.version` 为 3。

`src/story-speech.ts` 使用浏览器 `speechSynthesis`，优先设备本地的简体中文声音，需点击才朗读。遵循存档音量；静音或零音量时按钮明确提示开启声音，点击后才启用（零音量恢复为 60%）。不支持 API、无中文声音或播放失败时保留文字。关闭或替换面板会取消请求、停止朗读，并忽略迟到响应；故事弹窗期间沿用城镇暂停计龄规则，不再等待委托计时。没有新增音频资源或语音后端。

`src/town-history.ts` 管理百年城景。存档 `mortal.scenery` 保留 `lastVisitAge` 与 `revision`，新增可选的固定年岁基准 `since`。`townVisit()` 每次真正入城更新 `lastVisitAge`；新档以首次入城年岁初始化 `since`，缺少该字段时以已保存的 `lastVisitAge` 初始化，没有城景记录时才以本次入城年岁为基准。后续入城不重置 `since`，`townSceneryLayout()` 按 `floor((lastVisitAge - since) / 100)` 直接计算当前阶段，频繁回城也会累计推进；长别不逐年循环。旧 `revision` 保留作房舍分配基底，不再每百年递增或让全镇迁位。

- 事件：`session`（打开页面）、`run-start`（开局 / 天劫）、`run-end`（通关、落败、主动结束或天劫成功）、`town`（走进青岚镇）、`reincarnate`（寿尽、天劫、终章离界传承、主动四种原因；命盘重抽不计；协议中的 `result=epilogue` 保留）、`epilogue`（叩门）、`error`（页面运行错误）、`sharing`（留影操作与二维码来源，固定动作见下文）。前六种附当前关卡、境界阶、年岁、历练次数、灵根、路线等数值；`error` 只带 `detail` 错误摘要（种类、错误名、信息与文件名行号，前端清洗控制字符并截断到 160 字符）。不含存档、闲聊、账号或设备信息。
- `src/error-report.ts` 在页面启动后监听全局 `error` 与 `unhandledrejection`：相同摘要每次加载只发一次，合计不超过 8 个不同错误，随报随 flush；同时展示独立于游戏界面的底部提示（进度已保存，可刷新重进或忽略）。提示与上报互不影响，任何一环失败都不阻断游戏。
- 匿名编号为随机 UUID，单独存于 `qinglan-telemetry-id`，不进存档、不随导出导入迁移；「关于」开关写 `qinglan-telemetry-off`，关闭即清空待发队列。存储不可用时本页使用临时编号。
- 事件先在内存排队，满 10 条、结算、轮回、叩门、留影操作、带来源进入或页面隐藏时以 `navigator.sendBeacon`（`text/plain`，无预检）一次发送，不支持时退回 `fetch keepalive`；失败静默丢弃，不重试、不阻塞游戏。
- Worker `POST /event` 沿用来源白名单，接受最多 4 KB、至多 20 条经过字段白名单校验的事件，按 IP 每 60 秒 60 次限流（`EVENT_LIMITER`），逐条写入数据集 `qinglan_events`（绑定 `EVENTS`），成功返回 204。本机来源只校验格式不写入。列映射：`blob1…7` 为事件、站点、版本、路线、灵根、结果或轮回原因、错误摘要或分享动作；`double1…10` 为关卡、难度、境界阶、历练次数、秒数、局内等级、斩妖、天劫轮次、年岁、是否新存档，缺省为 -1。数据保留三个月；Workers 免费版每天可写 10 万条、查询 1 万次，账号每日请求额度与 NPC 对话共用。

```bash
npm run stats            # 近 7 天
npm run stats -- --days=30
```

查询脚本使用本机环境变量 `CLOUDFLARE_ANALYTICS_TOKEN`（或 `CLOUDFLARE_API_TOKEN`，须有 Account Analytics Read 权限），可选 `CLOUDFLARE_ACCOUNT_ID`，未设置时读取令牌可访问的唯一账号。输出各站概览、各境开局与通关率、玩家最远通关、轮回原因、版本分布与运行错误，均按 `_sample_interval` 加权。上线验证写入的记录使用版本号 `verification`，查询时排除。修改事件字段需同步 Worker、查询脚本与本节；发布顺序为先 `npm run deploy:npc-ai`，再推送或部署静态站，Worker 未更新时前端上报会被拒收但不影响游戏。

## GitHub Release · 单机版

推送 `v*` 标签会触发 `.github/workflows/release.yml`。发布流水线使用 `npm run build:standalone` 编译、校验18MB产物上限、打包并创建GitHub Release；`v*`标签同时独立触发Quality gates与二进制门禁，不在发布job内重复单测。发布流程创建GitHub Release，并附带离线包及 SHA-256 校验文件。

```bash
git tag v0.0.1
git push origin v0.0.1
```

单机包只包含静态文件，无需部署 Worker 或其他游戏服务端。解压后在该目录启动任意 HTTP 静态服务器并打开其本地地址；不要直接双击 `index.html`。默认相对路径 `./`，可放在根目录或任意子目录。页面标题和「关于」版本号标注「单机版」。

本地构建：

```bash
npm run build:standalone -- --outDir artifacts/standalone --emptyOutDir
node --experimental-strip-types scripts/size-check.ts --dir artifacts/standalone
node --experimental-strip-types scripts/standalone-check.ts artifacts/standalone
```

`--mode standalone` 将编译常量 `__QINGLAN_STANDALONE__` 设为 true，不是运行时设置。NPC 闲谈使用本地对白，茶馆轮换收录的旧闻，不请求 AI 或配图；留影和评语均本地生成。本地旧闻维护在 `src/local-tea-stories.ts`，陆迟《不系舟》篇据 `docs/novel.md` 第2章的御剑、修剑情节改编，以旧纸上的印记留悬念，首次优先展示后再轮换其余三篇。战斗中的自动历练是本地策略，照常可用。匿名统计、错误和分享上报、调试入口、服务端白名单和外部广告 SDK 全部停用；即使使用官网来源或设置 `VITE_NPC_AI_URL` 也不能重新启用。单机包不包含监控页面，不加载公共字体，直接使用系统字体兜底。官网、源码和留影二维码保留链接，只有玩家主动访问才会打开。

单机版与联网版沿用同一存档格式，不增删游戏资源或改变战斗数值；浏览器存档仍按来源隔离，换地址用导出/导入转移。可选资源缓存仍需玩家主动点击，构建号包含模式，完整缓存按构建号区分。独立 Quality job 编译并检查单机包的标识、清单、监控缺席及后端地址残留，发布 job 不运行测试。`npm run build`、Pages 和 Cloudflare 的常规构建保持联网版；推送新 `v*` 标签自动发布单机 zip 和校验和，不改变官网构建模式。

## 激励广告位（provider 架构与 AdSense 接入指引）

四处广告位共用同一套 provider 接口（`src/ads.ts`）：复活（`showReviveAd`）、自选灵根与物资补给（`showRewardAd`）、借寿（`showLifespanAd`）。main.ts 只管界面与奖励判定；「算看完的时刻」由当前 provider 决定，任何 provider 不可用（未配置、SDK 加载失败、无库存、玩家中途关闭）都自动回退 5 秒占位倒计时，线上任何状态都能玩。

- **provider 接口**：`RewardAdProvider` 的 `prepare({ placement, signal })` 与 `play()` 仍共用完成和失败回调。`ads-platform-source.ts` 按需加载平台模块，`ads-platform.ts` 读取后台供给快照并选择自营或 Google；取消后的迟到配置和 SDK 回调无效。新增平台需实现接口并同步平台协议、后台选项与校验。
- **占位 provider**：无投放、配置或网络失败时沿用 5 秒占位倒计时，奖励规则不变。
- **AdSense provider（`src/ads-adsense.ts`）**：按后台发布商 ID 注入官方 H5 SDK，测试模式通过 `data-adbreak-test` 设置，四个 placement name 使用后台值。默认名称为 `qinglan-revive` / `qinglan-reward-root` / `qinglan-reward-supplies` / `qinglan-lifespan`。SDK `beforeAd` 后接管观看时钟，仅 `adViewed` 算看完；无库存、脚本被拦截和未完成观看均回退占位。真实 Google 投放需本人先完成官方站点审核及 H5 游戏广告资格确认；本地受控 SDK 测试不能作为真实库存或审核通过证据。
- **奖励发放**：仍在游戏原有领取点执行（复活、灵根洗练、`adSupplies(save.unlocked)`、借寿），SDK 不改游戏数值；统计领取回调只在原保存及应用完成后执行。物资补给不按现实日期限次；`ad-reward-limits.ts` 统一判断供奉与所有资源不足入口的冷却。领取按当前大境界确定 10/25/50/100/200/500/1000 年（大乘及真仙沿用 1000），成功写档才应用 `suppliesReadyAt = age + cooldown`，突破不重算。结构版本 35 新增 `suppliesReadyAt`，缺失默认 0，非法值拒绝读取/导入，同版导出往返保留到期年岁。借寿每世最多三次，沿用 `adUsage.lifespan`，旧计数不清零，取消、加载失败或拒写不消耗；新世由 freshSave 重置两项。无界面辅助策略同样遵守冷却与三次借寿，冷却停止记 `supplies-cooldown`，借寿用尽按 `expired` 结算；不改变裸开荒样本和验收阈值。
  `src/common-ui.ts` 收纳首页、洞府与战斗共用的纯展示片段，只按参数渲染 HTML，不读写全局游戏状态。新增同类片段时优先放这里，保持 `main.ts` 只做状态衔接与事件路由。

## 开发时保护正在运行的游戏

当前按用户要求直接在 master 迭代，5173 使用生产预览。有人正在游玩时，不重启或热刷新游玩服务；先构建到临时目录，发布时先补齐资源、保留旧 hash 文件，最后原子替换入口 HTML。不要直接清理正在服务的 dist。直接修改现有页面并更新正常入口，验证直接访问 5173 首页；禁止另建临时 HTML、测试页或入口副本。新增素材必须先落盘、检查所有路径可加载，再接入资源清单，并通过 Chrome DevTools MCP 验证。不同端口的 localStorage 相互隔离，测试端口不会继承游玩端口存档。

`src/chronicle.ts` 管理有上限的此世年表和独立成就，修为增长统一经 `gainCultivation()` 记录跨境年岁，结算通关后再记录真仙突破；载入时用未知年龄补录，不生成虚构时间。`src/chronicle-ui.ts` 复用弹窗并转义存档文本。`src/spirit-power.ts` 通过隔离的一级入场预览复用实际战斗属性，只在首页或履历打开时计算，不加入帧循环。新增 `Game.elapsedYears` 从 0 累计正常历练每次推进的 `save.age` 实际增量并随对局保存；暂停、选技、后台未模拟时间及独立天劫不计，寿尽或天劫截停只累计到实际边界。缺失该字段时保持 unknown（`undefined`），不反推，也不把后续增量当作完整本局年岁。仅首次正常历练结算后直接返回首页时，复用顶部 toast 约 3 秒显示「山中一程，人间已过 X 年。」，X 取该累计值；unknown 不补提示，直接下一局不强插首页。

`src/journey-card.ts` 仅在点击履历底部、寿终 / 天劫殒命页或终章顶部「留存此世」时通过动态 `import()` 加载，复用现有山水、玩家与法宝图集，在本地生成 1080 × 1740 PNG 纪念图，不新增游戏图片或存档备份格式；叩入仙门使用与终章一致的晨光山水，其余状态使用暮色山水。内容取当前境界、行年 / 寿限、五行命盘、本命法宝、路线、宗门身份及最多四项真实存档记录，以两列两行展示；已达成成就按难度由高到低排列，并排在六仙同御和渡劫次数之前，不补造缺失历史。人物周围的色彩与法阵按当前境界变化，并按状态标「仙途未尽」「此世寿终」「止于天劫」或「已叩入仙门」。寿尽或天劫失败并确认放弃后，先保留原本世数据进入落幕页，由玩家自行留影后再确认轮回。`uqr` 是仅用于二维码生成的运行依赖，`jsqr` 仅作测试解码、不进生产包；卡片网址读取 `src/setting.ts` 的 `GAME_SITE_URL`；二维码经 `sharing.ts` 附加固定 `from=journey-card` 来源标记，不含存档、身份或个人分享ID。使用米金底与墨绿码，保留四格浅色静区并以整数像素绘制。修改官网配置后重新构建，部署域名绑定和 Worker CORS 白名单仍需独立维护。弹窗提供预览、下载及手机长按保存，关闭返回原履历、落幕页或终章，不改变此世状态；不上传图片或存档，不加奖励、账号、排行榜或新菜单。

宗门欠费以成员账期已到为待补缴状态，不依赖临时弹窗或额外墙钟。`advanceMortal()` 停在欠费节点，`settleSectDues()` 负责补缴或放弃清退；广告复用原物资奖励，未领取不发奖。与精研同刻到期的零剩余活动可存档，补缴后结算，放弃时取消。

`src/hometown.ts` 管理此世故乡状态，父母按 `save.age` 推导年岁与生死，不加入普通镇民换代名单。开局顺序为序章、故居告别、步行、离乡待命盘（`reveal`）、确认进入首页（`departed`）；灵根在 `freshSave()` 中固定，不在揭示或读档时重抽，刷新 `reveal` 恢复命盘。离乡前的 `root` 阶段按告别（`farewell`）处理，已经 `departed` 的档不重复开局。缺失家庭记录的本世不补造，轮回重新生成并保留 `hometownSeen` 跳过步行资格；发现家书与展读分开记录。`townDockPath()` 只在点击导航时计算路径，移动沿用当前城景碰撞，手动操作接管，到渡口后仍需确认离乡。

在世父母返乡交谈复用 `mountNpcChat()` 与现有 Worker，无新增开关；离乡三句叮嘱保持固定，AI 不可用时使用本地默认对白。除现有请求字段外仅附家庭片段 `hometown`，不上传完整存档；Worker 校验离乡与在世状态，模型提示中的家庭事实仅包含当前年龄及亲属在世情况，不传入 `diesAt` 等未来寿数。聊天不改数值、不发奖、不改任务。

`Game.loot` 记录本局实际入库的永久收藏法宝和丹药数量，随快照保存；`src/run-loot-ui.ts` 只渲染最终结算常驻的「此行收获」，同药合并，不重新发奖，替代对应掉落 toast。旧快照缺少 `loot` 时以 `complete: false` 标记，只累计后续收获并说明此前未载，不从背包反推。

觉醒同轮对王衰减集中在 `Game.hitEnemy()`，只有带 `bossAttack` 的子攻击且目标为非独立天劫的妖王才生效。同次施法共享 `volley.hitBosses`，每个子攻击另存目标倍率；火球直击与爆炸共用该倍率，不修改弹丸基础伤害。快照以 `bossVolleys` 表保存共享关系，弹丸引用索引，读取时校验并重建；无长期注册表，弹丸消失后上下文随引用释放。旧弹丸缺少记录时保留原伤害。`resetLifetime()` 默认直接进入新命盘，圆满终章改为离界后由十五岁青年接续，保留故乡选择及可选完整开场；普通主动轮回仍可显式选择完整开场。青年来历使用既有 `chronicle.milestones['immortal-successor']` 和一条承缘事实记录，完整保存及导出导入，无需新增存档字段或递增 schema；无赠物也记录，接受后保留，命盘重抽从旧来历重新记一次，不复制旧履历，普通轮回清除。

`src/image-share.ts` 使用 Web Share 文件接口：预览时准备 PNG File，点击后立即调用系统面板，避免异步转换丢失用户激活；取消不下载，不支持或失败时降级保存。生成图片不上传存档，分享仅按用户选择把图片交给系统应用，预览关闭后不触发迟到下载。

丹方由本世 recipeSeed 与固定丹药标识计算；灵品八方、限时珍品八方分别按材料及份数去重，颠倒材料顺序仍算同方。不冲突的原始配方保留，仅为后出现的重复配方分配尚未占用的组合，不抢占其他原始丹方。查询顺序、购方、刷新及存档往返不会重新抽方；材料仍只取低一品级两种成丹，灵品共三份、限时珍品共四份。购方及付费抄录不检查玩家境界或已解锁秘境，原80/200灵石价格、对方真实知识和保存预检保留；实际开炉仍检查秘境进度。品级筛选根据当前用途的实际药品显示，隐藏空品级，失效选择退回全部。

药铺每十年换三种凡品，整组抽回旧批时从本次剩余五种中替换一味，保证至少更换一种；周期、三份额度与价格不变。拍卖同批丹药及法宝分别按种类标识去重，不以委托人或炼器阶数当作不同品种；保留原槽索引、药物品级、永久丹触发与法宝会场炼器范围，已结拍卡片沿用真实成交记录。

拍卖法宝上架范围取 AUCTION_HALLS：人字场0～2阶、地字场3～6阶、天字场6～10阶；天字场起拍至少 AUCTION_PREMIUM_MIN_VALUE（1000）灵石，用实际估值验收，不改物品估值公式或玩家委托出售条件。坊市地图只保留建筑原名称牌，院落功能提示在交互面板内展示，不另放地面副牌。洞府恢复完整境界展示、灵根寿元、境界路标、根基修习顺序；现行属性公式与修习消耗保留。

妖物志专用的技能名称与说明集中在 `regional-skill-info.ts`，只随妖物志按需加载；战斗核心只使用其类型。敌方控制参数集中在 `regional-hazards.ts`：雷麻禁锢0.65秒、魂弹封宝1秒，减速、禁锢与封宝各自1秒再次触发保护。快照保存剩余时长和再次触发时间，老快照字段缺失取0，当前存档结构已递增。第二至第六境普通、精英与妖王出生伤害额外乘1.1，统一在enemyCombatStats计算，首境、终关和独立天劫排除；妖物志复用同一来源，技能与读档不重乘。自动施法冷却在封宝期间减到0后等待，解除时正常施法，不积攒多轮补发。

## 手机方向与镇坊切换

MobileDisplay在明确入场或方向选择时请求全屏，再通过按需模块orientation.ts锁定portrait/landscape；默认system不申请方向锁。选择独立保存到本机qinglan-screen-orientation，存储失败不部分应用，不修改SaveData或SAVE_SCHEMA；全屏退出、回首页和迟到锁定均释放本游戏的锁，不退出用户原有全屏。缺少Screen Orientation API时设置不申请全屏，锁定拒绝或实际方向不匹配时解除方向锁并退出本游戏申请的全屏，失败不阻断游戏；原生锁定两秒无响应即失败还原；请求代次与超时标记隔离，迟到结果只核对最新实际方向，已正确的新锁不动，转偏时仅修复当前选择；修复再失败也还原并更新当前提示。system选择立即解除并退出，不等待挂起的锁定。退出失败保留本次全屏归属，允许再次还原，不冒称成功；MCP触屏与原生接口夹具不等于实体手机锁屏测试。模块纳入原离线清单和当前版本重试。

镇坊快捷入口由SettlementPassage挂在原离开按钮左侧，随场景销毁清理，共用travelSettlement的先保存后切换及真实入场结算。button入口只跳过距离判断，保存失败保留原图；一年内换回不刷新人物或交易额度，回镇用正常故居落点，步行古道仍用安全路口落点。地图镇口复用人间图集灯笼门，坊市南口保留坊市图集的青瓦门楼，不再使用大幅说明牌；入场时统一把触发区及80像素复位区内的旧坐标移至安全落点，覆盖按钮与普通重进入口，行走中不改坐标。

### 成就圆满与概率寻访

履历成就印记由 `achievement-art.ts` 按稳定成就ID生成十五种内联SVG，随 `chronicle-content.ts` 按需载入；只读取达成状态控制印色，未知ID不渲染，名称、条件与年岁保留，SVG对辅助技术隐藏。图案不引入资源请求、字体、动画、存档字段或依赖，普通顶部文字提示与留影数据沿用原流程。

成就定义在 `chronicle-achievements.ts`，因洞府履历入口显示「成就 x/15」而随首屏入口加载；完整履历面板仍经 `chronicle-source` 按需加载。`chronicle.ts` 的 `ACHIEVEMENT_IDS` 是其余十四项的唯一集合；「万古独尊」（peerless）不参与自身条件，并排除当前birthInheritance或本世birth-inheritance里程碑；遗物用掉或售出后仍排除，只留指引的immortal-successor不排除。实际新增里程碑后即时检查，十四项齐备才记录，重复结算不重记。旧档按可证明的十四项补录后再判定，达成年岁仅在十四项年龄全知时取最晚值，否则留作年岁未载。已撤的慧眼识珍不再补录或触发，原拍卖成交与年表保留；留影优先展示圆满成就，评语事实与校验共用实际条件。

法宝及执事堂物品寻访由 `seeking-chance.ts` 统一取当前十年行情，公开机会35%～70%，宗门另加5个百分点；成功率始终低于100%。法器阁零阶法宝按180估值、执事堂按实际物品估值，酬金是估值×机会×135%向上取整；宗门弟子/执事/长老分别用115%/110%/105%，普通零阶法宝各次最低理论期望支出仍高于90%估值的最高合法出售净回款，不以某次抽中后盈利当作套利。各物行情随本世种子、物品、十年周期固定，短进出不换价；实际成败由本世种子、物品种类/id与已付费完成次数固定，换坊市/宗门/执事堂入口、刷新或保存失败重试不重抽。每次成功或失败都结清一年费用、到期供奉和办毕后十年冷却；只有成功才入库或清旧遗宝/出售标记，宗门提示不得将失败写作寻得。

存档结构31在 `mortal.marketVenues.seeking` 保存各物尝试次数，缺失为零；键仅允许实际法宝/丹药，次数为非负安全整数。按既有规则导入旧档保留永久进度，同版本导入导出完整保留次数；普通旧格式未完战斗不续，极限未完战斗沿原中断规则处理。奇物仍使用原有逐件次数、首访20%且失败递增至70%的规则，不跟随物品行情或改为必得。

### 广告小JSON的手机兼容读取与诊断

广告公开小JSON保留fetch(credentials:omit)、单次含正文6秒、瞬时故障一次重试和整轮30秒，不改为会在同源自动带Cookie的XHR。响应流和TextDecoder齐全时仍逐块限制；缺能力时用原生Response.text读取，已知Content-Length先检查，完成后按UTF-8字节检查上限再解析。兼容回退的大小检查发生在原生读取后，不能声称能够逐块截断；Worker请求正文及Siteverify仍用原有严格流式上限，不采用此客户端回退。控制器取消仍覆盖正文读取，取消后迟到数据不生效。
